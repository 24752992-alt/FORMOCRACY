# FORMOCRACY 眼镜对接手册（游戏端集成指南）

> 本手册面向**游戏端工程师 / 其 LLM 编程助手**。照着做即可让 Godot 游戏把事件推送到 Rokid AR 眼镜上显示/朗读。全程只需改动游戏端，无需了解眼镜端实现。

---

## 0. 一句话概览

游戏（Godot，WebSocket **客户端**）→ 眼镜手机 App（WebSocket **服务器**，端口 `8777`）→ AR 眼镜显示/语音。

```
┌──────────────┐   ws:// 发送 JSON 事件   ┌───────────────────────────┐   蓝牙/WiFi-P2P   ┌─────────┐
│ Godot 游戏    │ ───────────────────────► │ 眼镜手机 App (WS 服务:8777) │ ───────────────► │ AR 眼镜  │
│ (你负责这端)  │                          │  收事件→渲染卡片/朗读台词    │                  │         │
└──────────────┘                          └───────────────────────────┘                  └─────────┘
```

- 中间**不需要**任何 Mac 服务器 / Hono / 云端。就是游戏直连眼镜手机的局域网。
- 你要做的全部事情：**把 `RealityBridge.gd` 挂进 Godot 工程 + 填对眼镜手机的 IP + 在游戏逻辑里调用它的方法**。

---

## 1. 前置条件（必须同时满足）

1. 游戏所在电脑 与 眼镜手机 连**同一个热点/局域网**。
2. 眼镜手机 App 已打开，其状态栏显示形如：`游戏连接地址：ws://<眼镜手机IP>:8777`。
3. 你从眼镜端同学处拿到当前的 **`<眼镜手机IP>`**（例：`172.20.10.7`）。

> ⚠️ 热点重连后眼镜手机 IP 可能变化，变了要重新填。

---

## 2. 集成步骤（按顺序做）

### 步骤 A：放入桥文件
把随包的 **`RealityBridge.gd`** 复制到 Godot 工程根目录（即与 `project.godot` 同级，路径为 `res://RealityBridge.gd`）。

### 步骤 B：注册为自动加载单例（AutoLoad）
Godot 编辑器 → **项目 → 项目设置 → 全局 → 自动加载(AutoLoad)**：
- 路径选择 `res://RealityBridge.gd`
- 节点名称填 **`RealityBridge`**（必须一字不差，游戏里靠这个名字调用）
- 点“添加”，确保“启用”勾选。

等价地，`project.godot` 里应出现：
```ini
[autoload]
RealityBridge="*res://RealityBridge.gd"
```

### 步骤 C：填写眼镜手机 IP（二选一）

**方式一（改代码）**：打开 `RealityBridge.gd`，修改这一行：
```gdscript
const DEFAULT_HOST := "192.168.1.100"   # ← 改成眼镜手机 App 显示的 IP
```

**方式二（不改代码，推荐，换热点更省事）**：启动 Godot / 导出的游戏前设环境变量：
```bash
GLASS_WS_HOST=<眼镜手机IP> GLASS_WS_PORT=8777 /path/to/Godot --path /path/to/your/project
```
环境变量优先级高于代码里的 `DEFAULT_HOST`。端口固定 `8777`，一般不用改。

### 步骤 D：自测连通
在任意脚本（或一个临时按钮回调）里调用：
```gdscript
RealityBridge.send_test()
```
- **成功**：眼镜画面立刻弹出“连接测试”卡片；Godot 控制台打印 `[RealityBridge] 已连接 <ip>:8777`。
- **失败**：控制台打印 `连接失败` 或反复 `连接 ws://... 后重试`，见第 6 节排错。

## 3. 事件 API（推荐用这些封装方法，别手拼 JSON）

`RealityBridge` 是全局单例，任意脚本里直接 `RealityBridge.<方法>(...)`。所有方法都是“发出去即可”，离线时会自动暂存、连上后补发。

| 方法 | 眼镜端表现 | 是否朗读 |
|---|---|---|
| `morning_briefing(day, lines, title="")` | 晨间指令：逐行居中列表 | 否 |
| `day_report(lines, day=0, title="每日结算")` | 每日结算：逐行居中列表 | 否 |
| `secretary_react(phase, parcel_no, weight, dest, due, applied=-1.0)` | 秘书据局势**云端 agent 即兴生成台词+语音+字幕** | 是（agent 语音） |
| `secretary_line(text)` | 秘书固定台词 | 是（TTS 朗读 text） |
| `secretary_daybrief(day, newspaper, decisions=[])` | **能力①** 把晨报+玩家过往决策喂给秘书，后台摘要成“谈资”并缓存 | 否（纯后台） |
| `secretary_briefing_chat(day=0)` | **场景①** 到公司时秘书借晨报阴阳过去的批复 | 是（agent 语音） |
| `secretary_pick_comment(form_id, title, action, remaining_slots=-1, fact_hint="")` | **场景②** 选/撤候选表单时秘书据随机心情心理暗示 | 是（agent 语音） |
| `secretary_chat_start()` | **场景③** 玩家按住“说话键”：打断秘书当前朗读，开启眼镜麦克风录音（镜上显“聆听中…”） | 否 |
| `secretary_chat_stop()` | **场景③** 玩家松开：停录音 → 语音转文字 → 秘书结合多轮记忆+当日谈资回话 | 是（agent 语音） |
| `npc_line(name, text, gender="", age="", portrait="")` | NPC 出场：左侧头像 + 打字机台词 | 是（打字机+人物音效） |
| `reality_receipt(title, body, severity="normal", day=0, form_id="", outcome="")` | 现实回执卡片（title + body） | 否 |
| `consequence(title, body, severity="warning")` | 后果回流卡片 | 否 |

### 参数取值约定
- `phase`：`"intake"`（新包裹到台）\| `"verdict"`（盖章受理后）。
- `severity`：`"normal"` \| `"warning"` \| `"critical"`（影响卡片强调程度）。
- `gender`：`"male"` \| `"female"`；`age`：`"young"` \| `"average"` \| `"old"`（决定用哪段人物音效）。
- `portrait`：可选，点名指定某张预置立绘（文件名不带扩展名，大小写/分隔符不敏感，如 `"NPC_female_young1"`），优先于 `gender/age` 自动匹配。
- `secretary_react` 的 `applied`：`intake` 阶段建议省略（不传或 `<0`）；`verdict` 阶段传玩家已贴金额，供秘书对结果表态。
- 秘书双场景（能力① + 场景①②）因果由眼镜端 agent **自行推断**，人设限定“只暗示、不断言因果、不报数字”；`secretary_pick_comment` 的心情由眼镜端每次**随机**选取。
  - `newspaper`：`Array[Dictionary]`，每项 `{"headline": 必填, "body": 可选}`；`decisions`：`Array[Dictionary]`，每项 `{"formId", "title", "decision": "approved|rejected|held", "day"}`。
  - 调用顺序：先 `secretary_daybrief(…)` 后台摘要好谈资 → 到公司时 `secretary_briefing_chat()` 开口；下班选件时每次动作一条 `secretary_pick_comment(…)`。
  - `action`：`"add"`（加入验收队列） \| `"remove"`（撤出）。
- 场景③实时搭话（push-to-talk）：`secretary_chat_start()` / `secretary_chat_stop()` 必须**成对**调用（建议绑定同一个键的按下/松开）；录音过短（<0.1s）会被当误触忽略；多轮记忆保留最近 6 轮，若当天调过 `secretary_daybrief` 会自动把谈资带进聊天；需要眼镜侧已授权麦克风（首次会弹授权）。

### 调用示例
```gdscript
# 每日开局
RealityBridge.morning_briefing(5, ["今日配额：12 件", "重点排查：医院急件", "违规将触发死亡回执"])

# 新包裹到台 → 秘书即兴反应（云端 agent 生成语音+字幕）
RealityBridge.secretary_react("intake", 12, 620, "District 7", 1.50)
# 盖章受理后（带玩家已贴金额）
RealityBridge.secretary_react("verdict", 12, 620, "District 7", 1.50, 1.20)

# NPC 出场说话
RealityBridge.npc_line("办事居民", "你好，我来办理一项业务。", "male", "average")

# 秘书固定台词（直接朗读）
RealityBridge.secretary_line("请出示您的相关材料证明。")

# 能力① 晨报谈资准备（玩家读完晨报/到公司前调一次，不出声）
RealityBridge.secretary_daybrief(5,
	[{"headline": "第七码头供水恢复", "body": "但多户居民仍断水"}, {"headline": "医院急件积压引发投诉"}],
	[{"formId": "water_permit_07", "title": "饮水许可", "decision": "rejected", "day": 4}])

# 场景① 到公司时触发晨报闲聊（秘书阴阳过去的批复）
RealityBridge.secretary_briefing_chat(5)

# 场景② 下班选/撤候选表单时，每次动作一条
RealityBridge.secretary_pick_comment("hospital_urgent_07", "医院急件", "add", 2, "未验收将触发死亡回执")

# 场景③ 玩家主动找秘书搭话（按住说话，如绑 T 键）
func _input(event):
	if event is InputEventKey and event.keycode == KEY_T:
		if event.pressed and not event.echo: RealityBridge.secretary_chat_start()
		elif not event.pressed: RealityBridge.secretary_chat_stop()

# 现实回执（严重事件）
RealityBridge.reality_receipt("第七码头 · 医院急件", "文件未验收 · 触发死亡回执", "critical")

# 后果回流
RealityBridge.consequence("配额未达标", "本区评级下调")

# 每日结算
RealityBridge.day_report(["Approved  12", "Rejected  3", "Errors  2", "Wages $48.00"])
```

### 连接状态（可选监听）
```gdscript
RealityBridge.glass_connected.connect(func(): print("眼镜已连上"))
RealityBridge.glass_disconnected.connect(func(): print("眼镜断开，自动重连中"))
if RealityBridge.is_connected_to_glass():
    pass  # 已连上
```

## 4. 底层接口与原始协议（仅在非 Godot 客户端 / 特殊需求时用）

若你不用封装方法，也可直接发原始事件：
```gdscript
RealityBridge.emit_reality_event("reality_receipt", {
    "title": "医院急件", "body": "文件未验收", "severity": "critical"
})
```

底层协议 = 一条 JSON 文本，通过 WebSocket 发到 `ws://<眼镜手机IP>:8777`。若你的游戏不是 Godot（自己实现 WS 客户端），直接发下面结构即可：

```json
{ "type": "reality_receipt", "day": 5, "formId": "hospital_urgent_07",
  "outcome": "void", "severity": "critical",
  "title": "第七码头 · 医院急件", "body": "文件未验收 · 触发死亡回执" }
```

### RealityEvent 完整字段表（眼镜端可识别的所有字段）
| 字段 | 类型 | 用于哪些事件 | 说明 |
|---|---|---|---|
| `type` | string | **必填，所有** | `morning_briefing`\|`secretary_line`\|`secretary_react`\|`secretary_daybrief`\|`secretary_briefing_chat`\|`secretary_pick_comment`\|`secretary_chat_start`\|`secretary_chat_stop`\|`npc_line`\|`reality_receipt`\|`consequence`\|`day_report` |
| `day` | int | 晨报/回执/结算 | 天数 |
| `formId` | string | reality_receipt | 表单/事务 ID |
| `outcome` | string | reality_receipt | `approved`\|`void`\|`delayed` … |
| `severity` | string | 卡片类 | `normal`\|`warning`\|`critical` |
| `title` | string | 通用 | 卡片标题 / NPC 名字 |
| `body` | string | 卡片类 | 卡片正文（只显示，不朗读） |
| `text` | string | secretary_line / npc_line | 要朗读的台词 |
| `lines` | string[] | morning_briefing / day_report | 逐行显示（不朗读） |
| `phase` | string | secretary_react | `intake`\|`verdict` |
| `parcelNo` | int | secretary_react | 包裹序号 |
| `weight` | int | secretary_react | 重量(克) |
| `dest` | string | secretary_react | 目的地 |
| `due` | number | secretary_react | 应收邮资 |
| `applied` | number | secretary_react(verdict) | 玩家已贴金额 |
| `gender` | string | npc_line | `male`\|`female` |
| `age` | string | npc_line | `young`\|`average`\|`old` |
| `portrait` | string | npc_line | 指定立绘文件名（不含扩展名） |
| `newspaper` | object[] | secretary_daybrief | 每项 `{headline, body?}`，今日晨报条目 |
| `decisions` | object[] | secretary_daybrief | 每项 `{formId, title, decision, day}`，decision=`approved`\|`rejected`\|`held` |
| `action` | string | secretary_pick_comment | `add`\|`remove` |
| `remainingSlots` | int | secretary_pick_comment | 验收机剩余容量 |
| `factHint` | string | secretary_pick_comment | 该表单已知后果的客观提示（可选） |

> 注意：JSON 字段名是 **camelCase**（`parcelNo`/`formId`），封装方法内部已处理好，手拼 JSON 时别写错。

## 5. 联调验收清单（你和眼镜端同学一起看）

调用 `RealityBridge.send_test()` 后，两端应同时出现：
- **眼镜手机 App 日志**：`游戏已连接：/x.x.x.x` 且 `收到事件：reality_receipt`
- **眼镜画面**：弹出“连接测试”卡片
- **Godot 控制台**：`[RealityBridge] 已连接 <ip>:8777`

三者都出现 = 链路打通，可以开始正式联调各类事件。

## 6. 排错

| 现象 | 排查 |
|---|---|
| Godot 控制台反复 `连接 ws://... 后重试` | IP 填错 / 两端不在同一热点 / 眼镜 App 没开 |
| `连接失败: <错误码>` | 检查 `DEFAULT_HOST` 或 `GLASS_WS_HOST` 是否为眼镜手机的真实 IP |
| 连上但眼镜无反应 | 眼镜端“连接眼镜”未就绪；让眼镜端同学看 App 日志有没有 `收到事件` |
| 事件发了但眼镜没朗读 | 只有 `secretary_line`/`secretary_react`/`npc_line` 会出声；卡片类只显示不朗读 |
| 时好时坏 / 突然断 | 热点开了“客户端隔离”，换热点或便携路由器；重连后 IP 变了要重填 |
| 明文 HTTP/WS 被拦 | 本方案用局域网 `ws://`，Godot 端无此限制；无需额外配置 |

排错时把 Godot 控制台里 `[RealityBridge] ...` 那几行发给眼镜端同学一起看，能快速定位卡在哪一环。
